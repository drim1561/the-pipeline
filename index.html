Daniel Rim — Job Search System

An AI-powered assistant that handles the repetitive, error-prone parts of applying to jobs — tailored resumes, tracker updates, follow-up drafts, and more.

What it is

This is a custom job search assistant built on top of Claude Code — an AI tool made by Anthropic. Instead of a generic chatbot, it has been configured specifically for Daniel's job search. It knows his resume, his real experience, his writing style, and maintains a live Excel tracker of every application.

The guiding idea: Claude handles reasoning and generation. Python scripts handle data integrity. Built-in guards enforce rules automatically. Nothing gets submitted without Daniel's explicit go-ahead.

Built-in Guardrails — always on

Em-dash guard: Warns if a cover letter, message, or follow-up contains an em-dash or double-hyphen the moment the file is written.
🗂️
No-delete guard: Warns any time a command tries to delete a file. Standing rule is to archive instead, so nothing is ever permanently lost.

/new-application
Skill — slash command
File:.claude/skills/new-application/SKILL.md
Scaffolds a complete, tailored application folder from a single job posting. Handles everything from JD capture through resume tailoring, tracker entry, and final QA — without inventing anything beyond real experience.

How to use

Type /new-application in Claude Code, then paste a job URL or the full job description text. The skill runs all steps automatically.

Steps — in order

  1. 1
    Load profile. Reads job-search.config.json for canonical figures, real experience, voice rules, and file paths. This is the single source of truth — nothing can be claimed beyond it.
  2. 2
    Capture the JD. Creates the company folder under applications/ and writes a .md file with title, company, location, salary, posting URL, ATS source, and the full requirements text.
  3. 3
    Screen fit (optional). For unclear fits, dispatches the job-fit-screener agent before investing tailoring effort. Skipped for obviously strong matches.
  4. 4
    Tailor the resume. Inspects the base .docx paragraph structure, decides edits by reading the JD, writes an edits.json spec, and renders a tailored copy via render_resume.py — with a dry-run diff before writing.
  5. 5
    Cover letter / outreach (only if warranted). Default is resume-only. If justified, reads voice-profile.md and drafts in Daniel's style. Em-dash hook auto-checks on save.
  6. 6
    Add a Leads row. Calls add_lead.py with a dry-run first. Deduplicates on posting URL. Refuses partial writes if the tracker is open in Excel.
  7. 7
    QA gate. Dispatches the application-reviewer agent to check figure consistency, no invented claims, voice compliance, and JD keyword coverage. Returns a PASS / NEEDS FIXES punch list.

Hard constraints

  • 🚫
    Never submits or sends — this skill only stages drafts.
  • 🚫
    Never invents or inflates — all figures must match canonical_figures exactly.
  • 🚫
    Never deletes — superseded files are moved to an archive folder.
/submit-application
Skill — slash command
File:.claude/skills/submit-application/SKILL.md
Run the moment an application is actually submitted. Turns the post-submit checklist into one command — tracker update, snapshot, calendar reminder, and follow-up draft.

When to use

Run immediately after you hit Apply on a job. This skill records a submission — it does not submit one. Provide the company name and role; the rest is looked up automatically from the config and tracker.

Steps — in order

  1. 1
    Load profile. Reads job-search.config.json for paths, tracker schema, and follow-up timing (first nudge = day 7, second = day 14).
  2. 2
    Update the tracker. Runs update_pipeline.py with a dry-run first. Sets Stage to "Applied", Last Activity to today, and Next Action to the follow-up date. If the tracker is open in Excel, it stops and tells you to close it.
  3. 3
    Snapshot what was sent. Creates a submitted_{date}/ folder and copies (never moves) the exact resume, cover letter, and JD into it. Writes a submission.md recording company, role, date, URL, ATS, files, and resume version.
  4. 4
    Calendar reminder. Creates an all-day Google Calendar event on follow-up day titled "Follow up: {Company} - {Role}" with the posting URL in the description. Falls back gracefully if the Calendar MCP is unavailable.
  5. 5
    Stage a follow-up draft. Writes a short, natural follow-up message in Daniel's voice for use on day 7. Reads voice-profile.md first. No em-dashes. Does not send it.

Hard constraints

  • 🚫
    Never submits or sends — records and stages only.
  • 🔒
    Only update_pipeline.py may write the tracker — no ad-hoc edits via any other path.
  • 📋
    Snapshot by copy, never move — original sent files remain in place.
/triage-inbox
Skill — slash command
File:.claude/skills/triage-inbox/SKILL.md
Sweeps the Gmail inbox(es) for recruiter and ATS replies, classifies each, cross-references the tracker, and proposes next actions. Closes the loop between "Applied" and what actually came back. Read-and-recommend — it never auto-replies, archives, or deletes.

Steps — in order

  1. 1
    Load profile + inbox map. Reads the config and recalls the inbox split (primary account = application/ATS replies; secondary = LinkedIn InMail). Sweeps whatever the connected Gmail account exposes, and flags any inbox it could not reach rather than pretending it was covered.
  2. 2
    Search. Runs targeted Gmail searches over a time window (default 14 days) — recruiter language, known ATS senders (Greenhouse, Lever, Ashby, Workday, Rippling), and each company currently active in the Pipeline. Skips job-alert and marketing blasts.
  3. 3
    Classify. Buckets each thread: interview/screen request, scheduling, recruiter question, rejection, offer, no-action acknowledgement, or other.
  4. 4
    Reconcile with the tracker. Matches each thread to a Pipeline row, notes the current stage, and flags mismatches — like an interview request on a row still marked "Applied."
  5. 5
    Produce a triage table. One row per thread — company, what arrived, current stage, suggested action, tracker update — sorted with interviews and time-sensitive items first.
  6. 6
    Stage the follow-through. Gives the exact update_pipeline.py dry-run command, offers to dispatch company-research for a prep brief, and can draft a reply in Daniel's voice staged as a Gmail draft (never sent).
  7. 7
    Summarize. Counts by category, what needs action today, and anything gone quiet past the nudge window.

Reply categories

Interview / screen
They want to talk or schedule a screen — top priority
Scheduling
Back-and-forth on a time for something already agreed
Recruiter question
They asked for availability, salary, references, or a form
Rejection
A no — mark the tracker row terminal
Offer
An offer or a verbal
No-action ack
Auto-confirmations ("we received your application")

Hard constraints

  • 🚫
    Never sends or replies — replies are staged as Gmail drafts only.
  • 🗂️
    Never archives or deletes mail — read-only on the mailbox (labels are opt-in).
  • 🔒
    Tracker only via update_pipeline.py, dry-run first — never advances a row on a guess.

Agent — subagent
File:.claude/agents/application-reviewer.md
Tools:Read, Grep, Glob, Bash
QA gate for a tailored application. Catches the one class of mistake that costs a candidate a role: inflated numbers, invented claims, voice violations, and missing JD keywords.

The four checks

  1. 1
    Figure consistency. Scans every number and metric in the document. Flags anything that deviates from canonical_figures (e.g., a model count that isn't "1,300+"). Quotes the offending line.

tracker-auditor
Agent — subagent
File:.claude/agents/tracker-auditor.md
Tools:Read, Glob, Grep, Bash
Read-only hygiene auditor for the Excel tracker. Reports a prioritized punch list of issues. Never modifies anything — surfacing problems is its only job.

The five checks

  1. 1
    Duplicates. Same company appearing twice in Leads, or twice in Pipeline.
  2. 2
    Stale stages. An active Pipeline row whose Last Activity is more than 7 days old, or whose Next Action date has passed. These need a follow-up.
  3. 3
    Missing data. Blank Date Added, Stage, or Last Activity where it should be set.
  4. 4
    Folder vs tracker mismatches. Application folders with no Pipeline row (applied but untracked) or Pipeline rows at "Applied" with no matching folder.
  5. 5
    Leads not promoted. A Leads row marked "In pipeline? = Yes" but absent from Pipeline, or vice versa.

Output format

TRACKER AUDIT - <date> Health: <clean | N issues> NEEDS FOLLOW-UP (stale / past next-action): - <Company> (<stage>, last activity <date>): <suggested next action> DATA HYGIENE: - <issue> -> <fix> FOLDER/TRACKER MISMATCH: - <issue> -> <fix>
render_resume.py
Python script
File:.claude/skills/new-application/scripts/render_resume.py
Formats-preserving .docx tailoring engine. Claude decides what to change by reading the JD; this script is the safe renderer that applies those changes while preserving all existing formatting.

How it works

Takes a base .docx and an edits.json spec, copies the base byte-for-byte, then applies targeted paragraph-text replacements. Only the text changes — fonts, styles, spacing, bold labels, and layout are all preserved.

Smart handling for "bold-label" lines like the skills section (e.g., Technical Skills: SQL, Python…): the bold label and colon are kept intact and only the body text after the colon is replaced, so it never inherits the wrong bold formatting.

CLI flags

--base
Path to the base resume .docx required
--out
Output path for the tailored .docx
--edits
Path to the JSON edit spec ({"replacements": [{"index": N, "text": "..."}]})
--list
List all paragraphs with index numbers and exit — used to find which indices to edit
--dry-run
Print a diff of planned changes without writing any file
add_lead.py
Python script
File:.claude/skills/new-application/scripts/add_lead.py
Appends a row to the tracker's Leads sheet atomically and safely. Handles deduplication, Excel lock detection, and partial-write prevention.

Safety model

  • ⚛️
    Atomic write: Writes to a temp file in the same directory, then os.replace() onto the target. A crash mid-write never corrupts the tracker.
  • 🔒
    Lock detection: If Excel has the file open, the replace fails with PermissionError. The script saves a .pending recovery file and exits with a clear message — no partial write is ever made to the real file.
  • 🔁
    Deduplication: Deduplicates on posting URL first (most reliable), then falls back to company + role match. A company can have multiple distinct open roles, so it does not dedup on company name alone.

Key flags

--tracker
Path to the .xlsx tracker required
--company
Company name required
--role
Job title / role
--url
Posting URL — used as the dedup key
--tier
Tier 1–4 from the fit screener
--dry-run
Print planned changes without writing
--update
If a matching lead exists (by URL), update its fields instead of skipping
--force
Add even if a matching lead exists (intentional duplicate)

Python script
File:.claude/skills/submit-application/scripts/update_pipeline.py
The only authorized writer to the Pipeline tracker sheet. Records application submissions with atomic writes, lock detection, stage downgrade prevention, and automatic Leads sheet sync.

    Lock detection: If Excel has the file open, writes a .pending recovery file and exits cleanly. No partial write ever reaches the real tracker.
  • ⬆️
    Stage downgrade guard: Maintains an ordered ranking of pipeline stages. Refuses to overwrite a later stage with an earlier one (e.g., "Phone Screen" → "Applied") unless --force is passed. Terminal outcomes (Rejected, Withdrawn, Offer) are always allowed.
  • 🔗
    Leads sync: Automatically flips the "In pipeline?" column on the corresponding Leads row to "Yes". Safely skips formula-driven cells.

check_emdash.py
Hook — PostToolUse
File:.claude/hooks/check_emdash.py
Trigger:PostToolUse (Write, Edit)
Automatically scans any file Claude writes or edits. If the file looks like a cover letter, outreach message, or follow-up note and contains an em-dash or double-hyphen, it fires a visible warning.

Scope rules

The hook fires only on files whose name matches terms like cover_letter, _message, outreach, follow_up, or inmail. It explicitly excludes resumes, JD captures, the tracker, and specs files — so it never false-alarms on legitimate content.

Forbidden characters

  • —
    Em-dash (U+2014) — the most common accidental insertion
  • –
    En-dash (U+2013)
  • --
    Double-hyphen — common in programmatic text generation

Design intent

Warn-only by design — the hook always exits 0 and never blocks work, even if it errors internally. The warning is surfaced as a visible system message so it can be acted on before the file is sent, not used as a hard gate that could interrupt a session.

guard_delete.py
Hook — PreToolUse
File:.claude/hooks/guard_delete.py
Trigger:PreToolUse (Bash, PowerShell)
Inspects every shell command before it runs. If it looks like a destructive file delete, fires a visible warning reminding to move to an archive folder instead.

Patterns it watches for

  • 💻
    PowerShell: Remove-Item, Erase, Remove-ItemProperty, Rimraf
  • 🐚
    POSIX shell: rm (with any flags), del, rmdir

Safe exceptions

Commands that clearly target temp files or system temp paths are allowed through without a warning — patterns like .pending, \temp\, /tmp/, $env:TEMP, and mkstemp are recognized as safe and do not trigger the guard.

Design intent

Warn-only by design — always exits 0 and proceeds. The standing rule is "move, never delete" so superseded files can always be recovered. The hook is a nudge, not a blocker.

voice-profile.md
Profile — writing style
File:.claude/voice-profile.md
Captures how Daniel actually writes so generated cover letters, outreach, and follow-ups sound like him — not like generic AI. Built from real writing samples (2018–2020). Every drafting agent reads this before writing a word.

The eight DNA traits

Trait 1
Warm and relationship-first
Writes to people, not at them. Often opens by referencing real shared context before stating a purpose.
Trait 2
Direct about intent
States the purpose in the first line or two. No throat-clearing or extended preamble.
Trait 3
Gracious, sometimes thanks twice
"Thank you again for extending this opportunity" — sincere, not performative.
Trait 4
Earnest and humble, never boastful
Honest about limits. No bravado. Confident through specificity, not superlatives.
Trait 5
Sequential rhythm for reasons
"One of the biggest things… Another aspect… The next thing… Lastly." This is the shape for "why this company" answers.
Trait 6
Conversational connectors
"This time around, however" / "Based on all the research I've conducted" / "I believe…"
Trait 7
Contractions throughout
I've, haven't, I'll, don't. Never stiff or robotic.
Trait 8
Measured enthusiasm
Genuine and positive. One exclamation point at most in a professional message.

Calibration note

Source samples are from 2018–2020 (student / early career). The warmth, directness, graciousness, and sequential structure are treated as durable personality traits. Formality and precision are dialed up one notch for senior Analytics / Data Engineering roles.

As newer writing samples from Daniel come in, this file should be updated to refine the profile further.

/prep-interview
Skill — slash command
File:.claude/skills/prep-interview/SKILL.md
Generates a tailored interview prep guide for a specific company and role. Maps the STAR story library to likely behavioral questions, surfaces the strongest stories for that JD, and adds smart questions to ask. Grounded entirely in documented, manager-backed experience — no generic advice.

Steps — in order

  1. 1
    Load the story library. Reads star-stories.md in full. Only stories documented there can be used — no invention.
  2. 2
    Load the JD. Reads the company's JD file from the application folder. If not found, asks the user to paste it.
  3. 3
    Load the Pipeline row. Reads the tracker for current stage, key contact, and notes — read-only.
  4. 4
    Run company research (optional). Dispatches the company-research agent if a prep brief doesn't already exist in the company folder.
  5. 5
    Identify 3-5 likely behavioral questions based on the JD's emphasis, company stage, and interview stage.
  6. 6
    Map stories to questions. For each question: recommends the strongest story, provides a 90-second spoken version, surfaces the manager quote to anchor it, and gives a backup story.
  7. 7
    Surface smart questions to ask — derived from the JD and company research, not generic.
  8. 8
    Pre-call checklist — interviewer LinkedIn, recent company news, format confirmation.

Hard constraints

  • 🚫
    Never invents a story — every narrative must exist verbatim in star-stories.md.
  • 🚫
    Never fabricates a manager quote — quotes must be lifted exactly from the library.
  • 📖
    Read-only — writes nothing to disk, only returns the prep guide as output.

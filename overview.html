A job search with a copilot, not an autopilot.

the-pipeline is a personal agentic system I built on Claude Code over months of daily job searching. It drafts, checks, tracks, and preps everything, and it submits nothing. Every send button in this process is pressed by me.

The line, stop by stop

What actually happens between a posting and an interview

Each stop is a small workflow I can run with one command. Skills only load when called, specialist agents handle one bounded job each, and anything mechanical runs as plain Python with no model involved.

  • STOP 1Capture

    A job posting goes in. Details are checked against the official listing before anything else happens, because scraped job data lies more often than you'd think.

  • STOP 2Screen

    A screener agent scores the role against my real stack and targets and answers one question: is this worth tailoring for? A fast no is a feature.

  • STOP 3Tailor

    The resume is rewritten toward the role's language, drawing only from a locked file of verified experience. Numbers cannot drift and claims cannot grow.

  • STOP 4Review

    A second, independent agent plays QA: every figure checked against the source of truth, invented claims failed, and a softer check that it still sounds like me.

  • THE GATEI read it. I submit it.

    The system has no way to apply on my behalf. It stages a finished package and stops. Reading the final documents and pressing submit is mine, every single time.

  • STOP 5Track

    After I submit, one guarded script records it: the tracker updates atomically, an exact snapshot of what was sent is preserved, and a follow-up lands on my calendar.

  • STOP 6Triage

    It sweeps my inbox, classifies recruiter and ATS replies, and reconciles them against the tracker. Suggested responses are staged as drafts. Sending is mine.

  • STOP 7Prep and debrief

    Interview prep is built from my own story library, not generic advice. Afterwards it logs what was asked, and a coaching layer grades the transcript so the next round starts sharper than the last.

Where it always stops

The guardrails are the point

Autonomy is easy to demo and hard to trust. These rules are wired into the system itself, not into good intentions.

  • It never submits, sends, or posts. Applications, messages, thank-you notes: all of it stops as a staged draft. There is no code path that sends anything anywhere.
  • It never invents experience. Every claim traces to one canonical fact file, and a reviewer agent fails any draft that stretches past it. The most useful thing it does is say no to itself.
  • It never deletes. Files move to archives with their full history. Closed applications keep every document, debrief, and snapshot they ever produced.
  • One writer touches the tracker. A single script with atomic writes, a stage-downgrade guard, and verification after every write. A real bad write early on taught me this one.
  • Guardrails warn, humans decide. Style and safety checks flag problems without blocking work. The system makes issues visible; it does not make choices.
Tuned to one person

Months of use made it mine

The interesting part was never automation. It's that every correction I gave it became a permanent part of how it works, layer by layer.

  • Verified facts, locked. Six years of real work in one canonical file. Model counts, project scope, the honest nuances included.
  • My voice, profiled. A writing profile distilled from things I actually wrote. It flags the tells of machine writing, right down to banning em-dashes.
  • Eleven stories, sourced. A STAR story library grounded in real performance reviews, each with a rehearsed closing line, fed into every prep guide.
  • Feedback, remembered. When I correct it, the correction is written to memory and holds across sessions. The dashed ring keeps growing.
  • Me, at the center. The one component that ships anything.
